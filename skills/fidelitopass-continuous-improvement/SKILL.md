## Activation Contract

Use at scoped recovery, a potentially reusable correction, or a relevant work close, including blocked work. Exclude routine execution without a learning signal and exploratory questions without a reusable conclusion. If project routing is absent, explicitly request or load this skill by path; do not assume automatic activation.

## Hard Rules

- Read the [procedure and record contract](references/implementation-details.md) before use. Recover only pertinent records from [learning.jsonl](learning.jsonl), then reconcile them with current owner evidence.
- Use [existing routing](../../AGENTS.md#intent-routing) and [document owners](../../AGENTS.md#documentation-routing) first. Do not create parallel indices, generic knowledge trees or duplicate authority.
- Apply only small, related, evidenced procedural changes inside active authorized scope. Propose anything requiring specific approval; never inherit publication, merge or deployment permission from this skill's construction.
- Keep one bounded review; never recursively improve the improvement process. Workers report findings; the coordinator alone consolidates registry writes.
- Use repository files without provider dependencies. Optional external memory is evidence only. Instructions are not enforcement or a universal cross-session guarantee.

## Decision Gates

| Observation | Action |
| --- | --- |
| Explicit general correction | Evaluate reuse immediately; recurrence is not required. |
| Permanent preference | Confirm enduring scope and reconcile with its owner. |
| One-off exception | Keep task-local; do not generalize. |
| Exploratory question or ambiguous incident | Do not infer a rule; clarify only if needed for current work. |
| Existing instruction missed | Diagnose selection, reading or application; repair the relevant route/procedure, not a duplicate rule. |

## Execution Steps

1. Select the affected responsibility/path and current owner; filter recovery before loading details.
2. Classify the observation; separate proven findings from provisional hypotheses.
3. At relevant close, review errors, rework, discoveries and validation once. Discard trivial or duplicate findings.
4. Choose permitted apply, propose or do not persist. Update one current entry per learning only when useful; leave an empty registry when none qualifies.
5. Verify changed mechanics and prose at their natural boundaries; after promotion retain only a short outcome and owner pointer.

## Output Contract

Report pertinent owners, classifications, evidence/confidence, decisions, paths/checks and unresolved limits. Distinguish local application from delivered integration. Workers return reusable factual findings for coordinator consolidation, not independent memory writes. Do not claim measured token savings or improved code without measurements.
