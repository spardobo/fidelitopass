# FidelitoPass implementation detail

## Domain and persistence

Use conventional Laravel roots and Eloquent relationships, scopes, casts, Policies, constraints, transactions, row locks, jobs, scheduling and query builder. Avoid formal layers, generic repositories/services, empty scaffolding, Strategy/condition-tree/expression rule engines and generic BaseActions. Use a focused `<Verb><Subject>Action::handle()` for consequential business commands; the Action owns its whole transaction. Routine edits stay direct. Add a Service only for a real cohesive capability, an interface only for a real substitution boundary. Keep provider network calls outside transactions; commit local truth and dispatch retryable, duplicate-tolerant Wallet sync after commit. One concrete Google Wallet integration maps payloads, creates/updates objects, issues save payloads and classifies provider errors; it does not decide eligibility. PostgreSQL is authoritative; Google Wallet is the only customer-facing pass, and Customer passes are not User accounts. Scope every pass operation to explicit authenticated Business ownership; public acquisition identifiers do not grant validation authority.

Use `docs/promotion-model.md` for exact point and progress semantics: one points-target Promotion mechanic; regular Visit = 1 point; each Promotion owns optional weekly recurring x2/x3/x5 whole-day or disjoint half-open timed windows per local weekday (touching endpoints allowed, overnight split across weekdays). No stacking, no Business-global or previous-Promotion inheritance. Drafts are editable; publication freezes goal, Reward title/description, local dates, UTC window, timezone and all Puntos extra windows even when scheduled. Reconfirm if Business timezone changes since draft review. Store immutable `points_awarded`; sum accepted Visits for that pass and Promotion; unique entitlement and one final redemption. Legitimate same-day repeat Visits are allowed; technical retries are idempotent. Persist `visited_at` as a database-generated `timestamptz`; never persist a duplicate Visit local date. No customer User model, multiple mechanics or generic rule engine.

Keep Laravel UTC; use `immutable_datetime` for rule-relevant instants, `timestampsTz()` where appropriate, database defaults/expressions for event timestamps where required, CarbonImmutable for local input/display and PostgreSQL `AT TIME ZONE` with the published Promotion timezone for weekday/time and deadlines. After relevant locks capture `clock_timestamp()` **once** as `operation_at`, reuse for validity, point rule and domain/audit timestamps; never use browser/app-host time or transaction-start `CURRENT_TIMESTAMP` for lock-sensitive decisions. Read-only phase queries use explicitly current PostgreSQL time. Use PHP string-backed enums and PostgreSQL checks for stored lifecycles, not derived phases. Avoid default SoftDeletes and blanket audit fields; attribute direct facts (`validated_by_user_id`, `redeemed_by_user_id`). Preserve already-applied migrations and existing data with forward migrations; see database standard for legacy point-window migration.

## Livewire and source presentation

Use new native Livewire multi-file components when PHP, Blade and colocated tests form one responsibility; preserve stable starter formats. Livewire owns form/interaction/validation feedback; Actions own consequential transitions. In components order meaningful **properties, lifecycle hooks, actions, optional private helpers, listeners last**; omit empty blocks. Apply [Flux-first component decisions](../../../docs/development/laravel-application-standard.md#flux-first-component-decisions) before choosing Flux or native HTML; use Alpine only for small client-only interactions. Isolate camera/scanner JavaScript. Manual-code input stays immediately below scanner during identification, including camera failure; the focused confirmation and result replace both controls afterwards in the same dialog. Use component `@script` for page-local interactions and configured Vite entry for shared JS/CSS; no standalone bundle, global inline script or duplicate pipeline. Make listeners/observers/timers/animation frames idempotent through navigation/morphs and clean up on removal; respect touch and reduced motion. Neither client nor Livewire state decides validity or redemption.

Pint defines PHP formatting; follow configured PHPStan/Larastan, native types, descriptive English identifiers, cohesive methods and clarifying early returns. Avoid vague Manager/Helper/Handler/Util names. Write top-to-bottom with whitespace and extract helpers only for real complexity/duplication. In Blade separate logical header/form/card/navigation/section/action blocks with indentation and genuinely blank source lines. For long views use brief **lowercase English semantic region comments** (e.g. `<!-- form actions -->`) before useful major regions, not every element; do not compress ordinary elements, nested directives or whole sections into one line or PHP strings. Keep English identifiers in DOM ids, fragments, data hooks and their linked references/tests. Put visible `{{ __('...') }}` or other `{{ }}` text on its own indented line inside tags including Flux labels, headings, links, buttons and options; short self-closing attribute-bound labels can stay on one line. Preserve inline whitespace needed for mixed text. JavaScript also needs descriptive names, focused functions, early returns, named intent and whitespace, avoiding dense handlers, obscure nested callbacks and needless helpers. Add English PHPDoc only for non-obvious generic/array shapes, invariants, units/timezones, concurrency/idempotency, security, provider timing or exception guarantees. Follow [PHPDoc and comments](../../../docs/development/laravel-application-standard.md#phpdoc-and-comments) for useful responsibility headings, including the canonical JavaScript separator style, and lowercase English internal rationale near constraints. Enforce that guidance without imposing an architectural template or duplicating its rules here. Assess readability separately from behaviour tests, without source assertions for comments.

All visible Blade copy (including placeholder, alt, title, accessibility labels and illustrative display data) uses Laravel translations; decorative `alt=""` is fine. UI Spanish is professional/neutral; labels use Pase, Promoción, Puntos extra. Code, technical docs, enum/log names and internal comments are English; keep internal code and HTML comments in lowercase English. Centralize generated Promotion copy for preview, public join, Wallet and operation results.

Production Monolog logs are JSON to stderr with stable event names and one shared request UUID; include useful non-secret domain context. Never log passwords, cookies, authorization headers, raw validation tokens, Wallet private keys, full save JWTs or sensitive provider payloads. Expected domain rejections get clear UI states; unexpected exceptions get safe messages/request ID and sanitized server context, never production traces. Prefer framework/deployment security headers; do not break Livewire with untested strict CSP.

Use Pest for new project tests where practical, preserve untouched Starter Kit PHPUnit tests. Choose evaluator unit/domain, PostgreSQL feature/integration, Livewire component, Wallet boundary fake/contract and selected Playwright journeys; avoid redundant assertions, fixed browser sleeps, and prefer semantic selectors with auto-wait. For uncertain framework behaviour inspect installed versions/config, targeted official Laravel/Livewire/Flux docs and installed source; avoid broad speculative API assumptions. Report unavailable evidence rather than guessing an API.
